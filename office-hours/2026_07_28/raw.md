Best practice: if the .aspx content lives in SharePoint and you want it available to Microsoft IQ / Foundry IQ, prefer the SharePoint in Microsoft 365 indexer rather than scraping pages yourself. Use granular inclusion and exclusion rules to target the actual sites, libraries, pages, or lists you want, rather than indexing an entire tenant by default. This reduces noise, improves retrieval relevance, and keeps index size under control. Microsoft’s Azure AI Search performance guidance explicitly recommends keeping indexes smaller where possible and being selective about schema fields and field attributes, because overly broad indexes and over-attributed fields can degrade indexing and query performance. https://learn.microsoft.com/en-us/azure/search/search-performance-tips

Lee Stott [Microsoft]Role icon, Microsoft — 11:44 AM
Guidance is 

Lead with Copilot Studio when:

Low-code makers or business teams are building.
The organisation already uses Power Platform.
The agent mainly lives in Teams, M365 Copilot, or business workflows.
Governance, connectors, and rapid delivery are more important than deep customisation.

Lead with Foundry when:

Professional developers own the solution.
The team already uses GitHub, VS Code, Azure DevOps, LangChain, Semantic Kernel, Agent Framework, CrewAI, etc.
You need advanced RAG, custom models, observability, evaluations, or multi-agent orchestration.
The agent is part of a broader application or product.

Use both when:

The user experience is in Teams/M365, but the intelligence layer requires advanced AI engineering.
Copilot Studio acts as the front door while Foundry provides models, retrieval, orchestration, evaluations, or specialised agents behind the scenes.
